# 対戦環境評価 v7

v7は、計算で予測した環境ではなく、ユーザーが提示した枠別の環境候補を評価の前提にする。
対象キャラを固定した状態で残り4枠を総コスト内に組み、完成デッキを固定環境の各デッキと12ターン戦わせる。キャラの順位は単体の火力・耐久・コスト比ではなく、この完成デッキの勝率下限で決める。

## v6からの変更点

- 予測使用率・所持率・自動生成したメタ環境を使用しない
- 環境表の各列を、その枠に現れる固定候補としてだけ使う
- 高コストのキャラは残り枠が弱くなる結果まで含めて評価する
- 低コストのキャラは、空いたコストで後続を強くできた完成デッキの結果で評価する
- 継続スキルは、後続への効果継承を含む12ターン戦闘で評価する
- デッキ例は「単体評価では見えない正しい運用」の検証候補として同じ戦闘に投入する。例であること自体を加点しない

## 入力

`src/data/metagame-v7-inputs.js` に、環境候補を枠ごとの名前配列、デッキ例を順番付き5体の名前配列として記録する。

名前はNFKC正規化、表記ゆれ、読み仮名、属性縛り、レアリティ表記を使って収録データへ照合する。照合結果と信頼度はレポートの `inputAudit.matches` に残す。`low` または `unresolved` の名前は、計算前に必ず確認する。

## 実行

火・コスト100の標準評価は次で実行する。

```powershell
npm run rate:metagame:v7 -- --input=fire:100
```

結果は `reports/metagame-ratings-v7/fire-100/report.json` とCSVへ出力する。ローカルで短い動作確認だけを行う場合は、次のように候補数と環境数を絞る。

```powershell
npm run rate:metagame:v7 -- --input=fire:100 --environment-count=5 --max-candidates=1 --auto-deck-limit=1 --turns=2
```

## 再開とクラウド実行

評価途中の結果は同じ出力先の `progress.json` に保存される。中断後は同じ引数で再実行すれば完了済みキャラを飛ばして再開する。

```powershell
npm run rate:metagame:v7 -- --position=next --time-budget-seconds=600
```

`--position=1` から `--position=5` は指定した枠だけを計算し、`--position=next` は未完了の先頭枠だけを計算する。全枠が揃った時点で `report.json` とCSVを出力する。

各環境候補を少なくとも1回含めるため、火・コスト100では指定値72より多い77環境デッキを使用する。

`.github/workflows/metagame-v7-cloud.yml` は `metagame-v7-results` ブランチに進捗を保存する。GitHub Actionsでは1回につき未完了枠を時間上限まで計算し、自動で次の実行を起動する。

`--partner-limit` は固定キャラの残り4枠を探すためのパートナー候補数、`--auto-deck-limit` はそのキャラごとに実戦再現へ送る自動生成デッキ数である。これらは探索を絞る補助値であり、最終順位そのものは戦闘結果だけで決める。
