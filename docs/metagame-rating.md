# 縛り別メタ環境評価

## 目的

単体性能や一つの対戦への「刺さり」ではなく、特定の縛り・特定の枠で想定される環境に対して、最終的にどれだけ勝ちへ近づくかを評価する。

順位が高いキャラクターほど使用候補になりやすい一方、実際の出現頻度には所持しやすさも影響する。そのため、戦闘順位と予測使用順位を分けて扱う。

## 評価する縛り

- 属性は `fire`、`water`、`wind` を別々に評価する。選択色を一つでも含む複属性と全属性も候補に含む。
- 総コストは帯に分けず、指定した上限値ごとに独立評価する。隣接するコスト値を並べることで、環境の連続的な変化を見る。
- 1～5枠目を別々に評価する。同じキャラクターでも枠が違えば、登場ターン、蓄積スキルターン、周囲の味方・敵が変わる。
- 2～4枠目は想定スキルターンとその+1を候補にする。最終5枠目は想定値4以上をすべて候補にし、重いスキルほど実際の発動率が下がる形で評価する。

## 環境を作る反復処理

1. HP、Power、スキル到達見込み、推定所持率から基礎環境を作る。旧方式のレポートがあれば、その予測使用率を25%だけ混ぜて初期環境にする。新方式のレポートがある枠は新結果を100%使用する。
2. 評価候補を対象枠へ先に固定し、そのコストを含めて残り4枠を予測使用率から生成する。
3. 総コスト、重複禁止、伝説1体制限を満たす候補専用デッキを作り、対象枠が実際に登場するまで前の枠から通常どおり戦わせる。
4. 全候補で同数の成立盤面を確保し、対象枠より後ろのキャラもスキルを保持したまま最大12ターンの勝敗を比較する。
5. 一次戦闘順位と推定所持率から、その枠の予測使用率を作る。
6. 予測使用率で環境を再生成し、全候補を最終評価する。
7. 一括実行では全属性・全コスト・全枠を複数周し、他枠の最終使用率も次周の環境へ反映する。

標的選択は均衡、撃破優先、スキル脅威優先の3方針を均等に含め、攻撃順は高Power順で再現する。2枠目以降は使用可能なスキルを原則すぐ使用し、蘇生だけはそのターンの撃破予測がある場合に使用する。

## 最終勝利評価

- 勝利を1、引き分けを0.5、敗北を0として盤面平均を取る。
- 12ターンで決着しない場合は、互いの残り人数の進行度と残HP差から0～1の途中評価を出す。
- 総合順位の第一基準は、少数の偶然で上振れした候補を抑えるための予測勝率95%信頼下限。
- 次に予測勝率そのもの、攻守均衡、有利獲得、対抗行動の順で比較する。

## 有利獲得と対抗行動

### 有利を作る行動

防御、かばう、回復、蘇生を対象にする。スキルなしの同一キャラクターと比べ、味方の交代・脱落を何回防いだかを計測する。

### 不利を防ぐ対抗行動

攻撃強化、連続攻撃、全体攻撃を対象にする。スキルなしの場合と比べ、敵の交代・脱落を何回増やしたかを計測する。

属性変更は攻守どちらにも働くため、実際に生じた味方維持と敵排除の両方を計測する。短縮と遅延は効果だけを無視し、キャラクター自体は通常候補として残す。

防御だけで攻撃が足りない候補を過大評価しないよう、味方維持60%、敵への進行40%の重み付き調和平均を攻守均衡値にする。どちらかが0なら均衡値も0になる。

## 所持率と使用率

現在は実使用ログがないため、次の仮定を初期値にする。

| レア度 | 基礎所持率 | 強キャラの上限 |
| --- | ---: | ---: |
| N | 97% | 100% |
| R | 95% | 100% |
| CR | 90% | 99% |
| ZR | 76% | 97% |
| MZR | 55% | 92% |
| 伝 | 10% | 40% |

強いキャラクターほど完凸所持者が増える前提で、戦闘順位が高いほど各レア度の上限へ近づける。所持率は環境への出現頻度だけに使い、既に所持しているキャラクターの戦闘性能は減点しない。

伝説は入手・限界突破が難しく1デッキ1体までという公式仕様を反映する。根拠は[伝説ゆるの仕様](https://eigomonogatari.com/densetsu-yuru-shoiyou/)を参照。実対戦ログや所持率調査が得られたら、この仮定を置き換える。

## 実行方法

一つの縛りを高精度で評価する。

```powershell
npm run rate:metagame -- --attributes=fire --cost=150 --position=2 --first-scenarios=18 --final-scenarios=72 --turns=12 --workers=6
```

総コスト150について、3属性・5枠を2周して相互に環境を更新する。

```powershell
npm run rate:metagame:grid -- --attributes=fire,water,wind --costs=150 --positions=1,2,3,4,5 --passes=2 --workers=6
```

総コスト100～200を10刻みで連続評価する。

```powershell
npm run rate:metagame:grid -- --attributes=fire,water,wind --costs=100:200:10 --positions=1,2,3,4,5 --passes=2 --workers=6
```

計算量が大きいため、最初は属性、コスト、枠を絞り、結果を確認しながら範囲を広げる。JSONとCSVは `reports/metagame-ratings/<属性>/slot-<枠>-cost-<総コスト>` に出力する。
