# キャラ画像の運用

図鑑は画像が未登録でも画像枠だけを表示します。未登録キャラに対する画像通信は発生しません。

## まず決めること

画像の基準キーはキャラ名ではなく **キャラID** にします。同名キャラ・表記ゆれ・別レアリティがあっても衝突しないためです。

## 少ない枚数から始める場合

1. 画像を `character-images/` に置く。
2. ファイル名を URL エンコードしたキャラIDにする。例: `fire-001.webp`。
3. `npm run build:character-images` を実行する。
4. `npm run build` で図鑑へ反映する。

マニフェストには実在する画像だけが入るため、途中までしか画像が揃っていなくても安全です。

## 数千枚を扱う場合の推奨手順

画像を手作業で一枚ずつ貼るのではなく、次の二段階に分けます。

1. 元画像を一括収集し、`ID, 元ファイル名, 権利確認状況` の対応表を一度だけ作る。
2. 対応表に沿って WebP または AVIF へ一括変換し、ID名へリネームしてアップロードする。

本番では画像そのものをアプリ本体リポジトリへ大量に入れるより、画像用のオブジェクトストレージ/CDNに置き、生成マニフェストのURLをその配信先にする運用が扱いやすくなります。アプリ側は既に URL マニフェストと遅延読み込みに対応しているため、配信先を切り替えても図鑑のコードは変えずに済みます。

画像の利用許諾・二次利用条件は、収集元ごとに対応表へ記録してください。

## 許諾済みサイトからの一括登録

`npm run import:lets-eiigo-images` は、許諾を確認済みの場合に限り、対応する図鑑ページから画像を取得します。名前がキャラデータと一意に一致した画像だけを保存し、既存ファイルは上書きしません。

- `character-images/lets-eiigo-sources.json` に、キャラID・元ページ・元画像URL・保存ファイル名を記録します。
- `character-images/lets-eiigo-unmatched.json` に、名前から安全に対応付けられなかった候補を記録します。
- 取得後は `npm run build:character-images`、続けて `npm run build` を実行します。

アプリ画面の「権利表記」タブには、アプリ固有部分の帰属、原著作物の権利者、許諾に基づく掲載、再配布禁止を表示します。
